# Satellite Data Source: Copernicus Sentinel-2 Level-2A (CDSE STAC)

> **Phase 1 Documentation: Satellite Data Acquisition Foundation**  
> *Notice: This document details the data source rationale, API structure, search mechanics, and download strategy for the Multi-Agent Environmental Analysis System.*

---

## 1. Why Sentinel-2 Was Selected

The European Space Agency's (ESA) **Sentinel-2** constellation (comprising Sentinel-2A, Sentinel-2B, and Sentinel-2C) was selected as the primary Earth Observation mission for this project for several compelling reasons:

1. **High Spatial Resolution**: Sentinel-2 provides 10-meter spatial resolution for key visible (Red, Green, Blue) and Near-Infrared (NIR) bands. This resolution is ideal for resolving field-level agricultural dynamics, localized forest fragmentation, and urban vegetation patches.
2. **High Revisit Frequency**: With twin satellites in a sun-synchronous orbit, Sentinel-2 achieves a 5-day revisit cycle at the equator and 2–3 days at mid-latitudes, providing dense temporal series essential for detecting phenological cycles and rapid environmental degradation.
3. **Spectral Richness**: 13 spectral bands covering the Visible, Near-Infrared (NIR), Red Edge, and Short-Wave Infrared (SWIR) spectrum enable diverse biophysical calculations, including NDVI (vegetation vitality), NDWI (water/canopy moisture), and NBR (burn severity).
4. **Open Access Policy**: The European Commission and ESA maintain an open and free data policy for academic and public research.

---

## 2. Why Level-2A (L2A) Is Preferred Over Level-1C (L1C)

Sentinel-2 imagery is distributed primarily in two processing levels:
- **Level-1C (L1C)**: Top-Of-Atmosphere (TOA) reflectance. These values include atmospheric distortion, aerosol scattering, and solar geometry variations.
- **Level-2A (L2A)**: Bottom-Of-Atmosphere (BOA) **Surface Reflectance (SR)**, generated by processing L1C data with the Sen2Cor atmospheric correction processor.

### Justification for L2A in Temporal Vegetation Analysis:
- **Atmospheric Normalization**: Surface Reflectance removes Rayleigh scattering, ozone absorption, and water vapor distortion. Because temporal change detection compares radiometric values across distinct dates ($T_1$ vs. $T_2$), using uncorrected TOA (L1C) data introduces false differences caused solely by seasonal atmospheric haze or sun angle shifts.
- **Integrated Scene Classification Layer (SCL)**: L2A products include a dedicated 20-meter pixel classification mask (`SCL_20m`) identifying clouds, cloud shadows, cirrus, snow, water, vegetation, and bare soil. This allows automated masking of corrupted pixels before calculating NDVI differentials.
- **Sub-pixel Multi-temporal Registration**: L2A images are orthorectified to a standard UTM grid, ensuring spatial overlap between observation dates.

## 3. Why Copernicus Data Space Ecosystem (CDSE) Was Selected

The **Copernicus Data Space Ecosystem (CDSE)** is the European Commission's unified, next-generation data dissemination platform, replacing the legacy Copernicus Open Access Hub (SciHub).

Key advantages:
- **Comprehensive European Archive**: Hosts the complete, official archive of Sentinel-1, Sentinel-2, Sentinel-3, and Sentinel-5P products.
- **STAC-Compliant Discovery**: Native STAC API enables standards-compliant spatial and temporal querying.
- **Dual Access Pathways**: Provides both S3-compatible cloud object storage (`s3://eodata/`) and standard HTTPS OData endpoints for individual band retrieval.
- **Stability**: As the official long-term infrastructure for Copernicus, CDSE guarantees sustained API availability for ongoing academic projects.

## 4. STAC API Overview & Endpoints

The SpatioTemporal Asset Catalog (STAC) specification provides a common language to expose geospatial data assets. CDSE implements the STAC API specification v1.0.0.

- **STAC Catalog Root**: `https://stac.dataspace.copernicus.eu/v1`
- **Search Endpoint**: `https://stac.dataspace.copernicus.eu/v1/search`
- **Sentinel-2 L2A Collection URL**: `https://stac.dataspace.copernicus.eu/v1/collections/sentinel-2-l2a`
- **Collection Identifier**: `sentinel-2-l2a`
- **Interactive STAC Browser**: `https://browser.stac.dataspace.copernicus.eu/`

## 5. Search Parameters & Filter Mechanics

Queries to `/search` are executed using HTTP POST with a JSON payload:

| Parameter | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `collections` | `List[str]` | Target collection identifier | `["sentinel-2-l2a"]` |
| `bbox` | `List[float]` | 4-coordinate bounding box `[min_lon, min_lat, max_lon, max_lat]` in EPSG:4326 | `[14.25, 50.01, 14.58, 50.13]` |
| `datetime` | `str` | ISO-8601 interval `"<start>/<end>"` | `"2024-06-01T00:00:00Z/2024-06-30T23:59:59Z"` |
| `query` | `dict` | STAC Query extension for attribute filtering | `{"eo:cloud_cover": {"lte": 20.0}}` |
| `limit` | `int` | Maximum items to return (1 - 250) | `10` |

### Asset Structure Representation
Each item contains 40+ granular assets in its `assets` dictionary. For vegetation analysis, the essential assets are:
- `B04_10m`: Band 4 (Red, 665 nm, 10 m resolution) — chlorophyll absorption.
- `B08_10m`: Band 8 (Broad NIR, 842 nm, 10 m resolution) — leaf cell structure reflectance.
- `B02_10m` & `B03_10m`: Blue & Green bands for True Color Composites (TCI).
- `SCL_20m`: Scene Classification Layer for automated cloud and shadow masking.
- `thumbnail`: Low-resolution overview image (`image/jpeg`).

## 7. Authentication Considerations

1. **Discovery / Metadata Search**:
   - **Zero Authentication Required**: The CDSE STAC search and catalog endpoints are fully public. Applications can discover scenes, evaluate cloud cover, and inspect asset URLs without an API key or account credentials.
2. **Asset / Raster Access**:
   - Downloading imagery or streaming bytes from CDSE requires a free user account registered at [dataspace.copernicus.eu](https://dataspace.copernicus.eu).
   - **OAuth2 Token**: An OpenID Connect (OIDC) access token can be acquired via POST to:  
     `https://identity.dataspace.copernicus.eu/auth/realms/CDSE/protocol/openid-connect/token`  
     with `client_id=cdse-public` and user credentials.
   - **S3 Access**: Users can generate S3 Access/Secret keys in the CDSE web dashboard to mount or access `s3://eodata/`.

## 8. Future Download & Band Access Strategy (Phase 1B+)

Downloading full Sentinel-2 `.SAFE` archives (~800 MB to 1.2 GB per scene) would quickly overwhelm local storage and bandwidth for an engineering mini-project. 

Therefore, our recommended download strategy:
1. **Targeted Band Retrieval**: Only retrieve the specific band files needed for the task:
   - For NDVI: Band 4 (`B04_10m.jp2` or TIFF) and Band 8 (`B08_10m.jp2` or TIFF) ~ 90 MB each.
   - For Cloud Mask: `SCL_20m.jp2` ~ 15 MB.
   - Combined download: ~195 MB per scene (an 80% reduction compared to the full SAFE archive).
2. **Spatial Windowing / Clipping**: In Phase 2, explore spatial window reads (using GDAL/rasterio VSI curl or OData chunking) to fetch only the bounding box sub-window rather than the entire 100 km $\times$ 100 km tile.
3. **Offline Sample Fallback**: Store one pre-downloaded dual-temporal sample pair in `data/sample/` so that unit tests, classroom evaluations, and offline demonstrations remain 100% reliable without live network dependencies.
